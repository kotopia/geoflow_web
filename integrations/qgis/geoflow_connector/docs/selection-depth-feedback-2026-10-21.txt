GeoFlow 객체 선택·심도 피드백·검색 반경 변경 보고
2026-10-21

1. 기존 선택 로직
layers/identify.py IdentifyGeometry.canvasReleaseEvent에서 canvas.layers()의 표시 순서대로
관리 레이어 목록을 만들고 TopDownStopAtFirst로 식별했다.

2. 제거한 동작
표시 레이어 전체 순회 및 레이어 순서에 따른 우선 hit test를 제거했다.
활성 레이어 없음/비관리 레이어에서는 다른 레이어로 fallback하지 않고 안내만 표시한다.

3. 활성 레이어 선택
ui/form_host.py에서 iface.activeLayer를 IdentifyGeometry에 전달한다.
layers/identify.py에서 QgsVectorLayer 및 관리 목록의 동일 객체인지 확인하고
단일 [active_layer]만 QGIS identify에 전달한다. 빈 목록은 전달하지 않는다.
빈 지도 클릭도 활성 관리 레이어의 선택만 해제한다.
[FEATURE_SELECT]에 활성 레이어, 후보 수, 선택 객체 ID를 기록한다.

4. 공통 기본값
services/settings.py GeoFlowSettingsService.DEFAULT_RADIUS_M = 2.0.
심도 및 맨홀 기본값도 이 상수를 참조한다. 기존 프로젝트별 override와 레거시 심도 설정은 유지.
이번 변경은 기본값 변경이며 저장된 1m/10m 등의 설정을 덮어쓰지 않는다.

5. 미터 거리
services/nearby.py에서 각 CRS 좌표를 EPSG:4326으로 변환하고 QgsDistanceArea의
프로젝트 타원체(없으면 WGS84)로 거리를 계산한다. degree를 거리값으로 비교하지 않는다.
공통 within_radius는 1e-6m 수치 오차만 허용한다. 생성 배치 중복도 이 함수를 사용한다.
심도 batch 공간 인덱스 사각형은 보수적으로 확장하고 최종 포함 여부는 미터 거리로 판정한다.

6. Depth source
현재 프로젝트, 삭제되지 않은 유효 Point, 기존 FACILITY/DEPTH 코드 분류 조건 유지.
관리번호 일치 우선순위를 유지하되 번호가 일치해도 설정 반경 안이어야 한다.
이전의 무제한 관리번호 검색을 제거했다. 반경 내 후보는 거리순으로 선택한다.
선택된 source의 Z가 없거나 유효하지 않으면 명확한 실패 결과를 반환한다.

7. H 탐색
정확한 H 코드 및 기존 활성/프로젝트 조건을 유지한다.
직접 계산과 batch 모두 설정 반경을 적용하고 후보 없음은 no_height_candidate로 반환한다.
[DEPTH_SEARCH]에 radius_m, survey_candidate_count, h_candidate_count,
source_id(계산 진단용 원본 측점 ID), result, reason을 기록한다.

8. 생성상태 검색
services/survey_spatial.py nearby_targets가 공통 기본 반경 2.0m 또는 프로젝트 override 사용.

9. 중복 검색
같은 함수로 대상 레이어, 프로젝트, ftr_cde, 실제 거리를 검사한다.
같은 배치 내부 points_overlap에도 동일 기본 반경과 수치 오차 규칙 적용.

10. Inline UI
ui/inline_message.py InlineMessage: QLabel 1개와 single-shot QTimer 1개.
DynamicForm.add_behavior_widget로 헤더 아래/폼 body 위에 설치한다.
ui/edit_tools.py calculate_current_depth에서 서비스 결과를 전달한다.
2800ms 뒤 숨기고, 반복 클릭은 기존 timer stop → text 교체 → timer restart.
객체/form 값 재로딩 시 이전 메시지는 숨긴다. 오류 결과에는 QMessageBox를 사용하지 않는다.

11. 실패 사유 표시
no_nearby_survey → 반경 N.Nm 이내에 심도 계산에 사용할 측량점이 없습니다. (주황)
no_height_candidate 및 이전 H 검색 사유 → 반경 N.Nm 이내에 표고 기준점(H)을 찾지 못했습니다. (주황)
invalid_source_z / source_z_missing → 측량점의 Z값을 사용할 수 없습니다. (빨강)
h_z_missing → 표고 기준점(H)의 Z값을 사용할 수 없습니다. (빨강)
그 외 / 예외 → 심도값을 계산하지 못했습니다. (빨강, 로그에 실제 사유 보존)

12. 성공 표시
✓ 심도값 2.000m를 계산했습니다. (초록)
음수 심도는 계산 결과와 함께 검토 안내를 주황색으로 표시한다.
폼에 값만 반영하며 기존 저장 정책은 유지한다.

13. 겹침 선택
실제 QgsMapCanvas, QgsMapMouseEvent, QGIS identify 엔진으로 검증.
Survey → Valve → Depth → Survey 전환 시 각 활성 레이어만 반환.
활성 레이어 없음/비관리 레이어는 선택 이벤트 없음.
표시 목록에서 제외한 활성 레이어도 해당 레이어만 식별.
활성 레이어에 객체가 없어도 겹친 다른 레이어 객체를 반환하지 않음.

14. 경계
QgsDistanceArea.computeSpheroidProject로 1.99/2.00/2.01m 점 생성.
source 검색, H 직접 검색, H batch 검색, 생성상태 검색, 배치 중복 판정 모두
1.99m 포함 / 2.00m 포함 / 2.01m 제외 통과.
