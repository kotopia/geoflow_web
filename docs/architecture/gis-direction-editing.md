# GIS 선택·심도·방향각 사용 흐름

2026-11-02 · Connector 1.4.7 검토 후보. 사용자가 지정한 QGIS default 프로필의 플러그인 파일을 직접 수정했다. 운영 서버 게시·DB 수정·정식 ZIP 덮어쓰기는 하지 않는다. 1.4.5/1.4.6 이력과 당시 제한은 Git 이력 및 [1.4.6 검토 기록](../operations/connector-1.4.6-review.md)에 남긴다.

## 운영 각도 계약

사용자가 기존 SQL/AutoCAD 작업 기준과 EPSG:5186을 확정했다. 저장값은 **EPSG:5186의 X·Y 좌표축, 동쪽 0°, 북쪽 90°, 서쪽 180°, 남쪽 270°, 반시계방향**, 범위 [0,360)이다. 진북·측지 방위각이 아니다. 북쪽 시계방향 방위각 A를 `normalize(90-A)`로 바꾸며 `normalize(degrees(atan2(dy,dx)))`와 같다.

`services/direction_math.py`의 공통 변환을 재사용한다. `operational_config`는 예전 중앙/로컬 설정의 북쪽·시계방향·offset·최장 UUID 정책을 이번 승인 계약(east/counterclockwise/offset=0/review)으로 런타임에서 해석한다. 원본 중앙 응답이나 QSettings를 읽을 때 변경하지 않는다. 설정 화면의 원점/증가 방향은 고정 표시하며 저장 시 로컬 rules만 이 계약으로 기록한다. 중앙 서버의 저장 설정은 이번 작업으로 변경하지 않았다. 향후 중앙 설정도 같은 계약을 사용해야 한다.

시설별 활성 중앙 필드 UUID, 기준선 레이어 UUID, 검색 허용거리, 심볼 보정은 중앙 Definition을 사용하며, 설정 UI에서 저장한 서버·프로젝트별 로컬 override가 있으면 이를 사용한다. field rename/추가/문자열 숫자 강제 변환은 하지 않는다. 기타시설 중앙 타입이 text이면 쓰기 가능한 숫자 필드가 필요하다는 사유를 표시한다.

## 검색과 선분

거리 검색은 시설점 중심의 미터 AEQD를 사용한다. **각도는 AEQD를 왕복하지 않고 원본 기준선 버텍스를 EPSG:5186으로 직접 변환**하여 계산한다. 지리 좌표의 경위도 차이를 각도로 저장하지 않는다. 기존 기하/CRS·설정 fingerprint로 적용 전 변경 여부를 재확인한다.

시설과 실제 가까운 선분/파트를 검색한다. 시점은 첫 유효 선분, 종점은 마지막 유효 선분의 **원래 버텍스 순서**를 유지한다. 내부 버텍스에서는 앞뒤 인접 선분을 검토한다. 연속 중복점·길이 0은 제외한다. 연결 방식은 버텍스 접속, 최근접 방식은 선분 중간 및 허용거리 내 이격 시설도 허용한다. 허용거리는 계산 의미를 바꾸는 각도 보정이 아니다.

동일 파트의 같은 위치에서 같은 방향의 직선 접선만 중복 제거한다. 0°와 180°를 합치지 않는다. 꺾임·다중 접속·동일 거리 후보는 최장 선분/UUID로 자동 선택하지 않는다. 단일 결과표에서 후보 한 개를 선택하며 일괄에서는 검토 대상으로 남긴다. 직접 회전의 180° 반전으로 사용자가 조정할 수 있다.

## 기존 SQL과 차이

기존 SQL은 첫 파트의 끝에서 두 번째 점→끝점을 사용하고, 방위각을 정수화한 뒤 CAD 기준으로 변환한다. 공통점은 좌표축 기준 각도와 원래 진행 방향이다. 신규는 시설 위치의 실제 파트/선분, 허용거리·후보 검토, 현재 프로젝트/중앙 저장 매핑을 사용한다. 과거 S_water/pj_code/angdir SQL은 실행하거나 이식하지 않는다.

신규 내부 계산은 소수 정밀도를 유지한다. 적용 직전 실제 정수 타입 또는 중앙 integer 의미에는 0자리, decimal에는 중앙 scale 및 실제 제공 precision 중 더 엄격한 값을 적용한다. 실제 double에 정의된 scale이 없으면 내부 값을 유지한다. 반올림은 Decimal ROUND_HALF_UP(정규화된 비음수 값의 .5는 위로), 반올림 후 360은 0이다. 일반 폼 숫자 입력도 변경된 방향각 필드만 같은 저장 변환을 사용한다. 다른 필드 저장 때문에 기존 각도를 정규화하지 않는다.

SQL의 `degrees` 결과는 double precision이므로 정확한 .5 처리에는 서버/플랫폼 의존성이 있다. 흔한 ties-to-even 정수화와 비교하면 A=89.5°에서 과거 `90-round(A)=0°`, 신규 `round(90-A)=1°`로 달라진다. A=90.5°는 두 방식 모두 0°로 정규화된다. 운영 SQL 실행 비교는 하지 않았으며 회귀는 이 산술과 경계값을 검증한다. [PostgreSQL 수치 반올림 문서](https://www.postgresql.org/docs/current/functions-math.html).

## 표시와 편집

저장각과 심볼 보정은 분리한다. EPSG:5186 지도에서는 QGIS 회전각이 `normalize(90-ang_dir+symbol_offset)`이며, 다른 지도 CRS에서는 5186의 1m 방향 벡터를 지도 CRS로 변환한 화면 방위각을 사용한다. 복합 마커의 상대 각도는 `setDataDefinedAngle`로 유지한다. [QGIS marker API](https://api.qgis.org/api/classQgsMarkerSymbol.html).

지도 손잡이도 EPSG:5186 방향을 지도 좌표로 변환한다. 숫자·다이얼·손잡이는 동일 저장값을 공유한다. 다이얼은 동쪽 0°·북쪽 90°를 직접 그리며 마우스 위치도 같은 축으로 해석한다. 미리보기는 임시 레이어만 변경하고, 취소는 편집 버퍼에 값을 쓰지 않는다. 적용은 기존 QGIS undo 및 저장 흐름을 사용한다. 수동 회전은 자동계산 기준선 없이 가능하다.

실제 심볼의 SVG/기본 방향 차이는 해당 시설의 명시적 symbol_offset으로 조정한다. 표시 보정은 저장값을 바꾸지 않는다. 과거 서로 다른 기준으로 저장된 객체를 일괄 변환하거나 추측해 복구하지 않는다. 운영 QML/SVG의 시설별 보정값은 임시 심볼 테스트만으로 확정하지 않는다.

## 기존 UI·저장 흐름

- 하나의 선택 버튼: 클릭 단일/드래그 다중, Shift 추가/Ctrl 해제/Esc 취소. 기존 관리 레이어 범위 및 선택 집합을 보존한다.
- 일반 아이콘의 심도 일괄계산: 지원 레이어·쓰기 권한·선택 2개 이상으로 활성화. 사전 편집모드/Survey/H를 요구하지 않는다. NULL만/전체로 기존 계산 코드를 실행한다. 성공·실제 변경·동일·건너뜀·실패와 객체별 값/사유를 결과표에 표시한다.
- Survey·심도·방향각은 공통 임시 하이라이트, 결과 행 위치 이동, 변경 전체 보기, 해제를 사용한다. 선택·속성을 변경하지 않는다.
- 메인 레일·편집 도구·폼 헤더·레이어 작업 영역의 일반 아이콘/배치는 ui/designer/*.ui가 소유한다. Python은 동작과 활성 상태를 연결한다. 동적 필드 액션은 중앙 UUID에 따라 부착한다.
- 중앙 기능 정의가 불완전해도 필드 오른쪽 자동계산/직접 회전 위치를 유지하고 툴팁/로그에 사유를 표시한다. 일반 field-action 숨김 설정은 두 버튼을 숨기지 않는다. 최신 Definition 조회 후 기존 폼의 버튼도 갱신한다. 과거 서버에서 capabilities 자체가 없는 경우에만 읽기 전용 감사로 확인된 두 중앙 필드/레이어 UUID 쌍을 호환 처리한다.
- 저장/취소 이동 guard는 재진입을 막는다. 폼의 원본과 provider 원본을 별도로 추적하여 자신의 QGIS 편집 버퍼 변경을 외부 충돌로 오인하지 않는다. 취소는 해당 객체의 변경만 되돌리고 다른 선택 객체의 버퍼 변경은 보존한다. 실패와 실제 provider 충돌은 입력을 유지하고 안내한다.

## 검증과 제한

QGIS 4.2.2 임시 레이어·Qt 위젯으로 계산·후보 선택·결과표·하이라이트·필드 버튼·미리보기·권한·저장/취소 이동을 검사한다. CAD 회귀는 8방향, 시점/종점/역순, 멀티파트, 중복/0길이, 교차/꺾임/반대방향, 정밀도/360, 복합 심볼, 다른 지도 CRS의 손잡이/렌더러, 파일 저장과 프로젝트 재읽기를 포함한다. 버전별 실제 결과는 release/1.4.7/에 기록한다.

운영 C26070/C26048 서버 저장 및 현재 적용 QML/SVG의 모든 시설별 표시를 직접 검증하지 않았다. 기존 객체는 시험에 사용하거나 자동 변환하지 않았다. 후보 ZIP은 별도 프로필로 검사하며 운영 게시/정식 ZIP 교체는 별도 지시가 필요하다.
