# 중앙 사용자·그룹 관리

## 목적과 원본

중앙 DB의 `users`, `groups`가 계정과 테넌트의 원본이다. 접속 설정은 기존
`GroupDBConfig → Secrets Manager` 경로를 유지한다. 테넌트 업무 DB에는 이 설정을 복제하지 않는다.

## 삭제 항목 표시

- 사용자·그룹 목록은 삭제 항목을 기본 숨기고 `모두 보기(삭제 포함)`로 표시한다.
- 비활성·승인 대기 계정은 삭제가 아니므로 계속 표시한다.
- 그룹은 기존 `groups.deleted_at`을 사용한다. 컬럼이 없는 기존 중앙 DB에서는
  삭제로 추정하지 않는다. 그룹 삭제·복구 절차 자체는 이번 변경 대상이 아니다.
- 사용자 익명화 시 `users.deleted_at`을 같은 삭제 트랜잭션에서 기록한다.
  실제 삭제된 사용자는 모두 보기에도 나타나지 않는다. 익명화된 사용자는
  `삭제된 사용자`로 표시하며, 감사 이력과 기존 개인정보 삭제 서비스는 유지한다.
- migration 0007은 기존 삭제 서비스가 생성한 정확한 UUID 익명 이메일 형식,
  비활성/미인증/비관리자, 비어 있는 이름, 사용 불가 비밀번호, 그룹 소속 없음이
  모두 일치할 때만 `updated_at`을 삭제 시각의 대용값으로 이관한다.
  런타임 목록은 이메일 문자열로 삭제를 판정하지 않는다.

## 그룹별 서비스 메뉴 표시

그룹 수정 화면에서 입찰·GIS·파이낸스를 각각 선택한다. 중앙 전용
`group_service_menu_settings`에 그룹당 한 행으로 저장한다. 기존 모델에 메뉴
설정 필드가 없으며 DB 접속 설정과 의미가 달라 독립된 작은 테이블을 사용한다.
행이 없으면 세 메뉴 모두 표시한다. 신규 그룹도 같은 기본값이다.

공통 사이드바는 그룹 설정과 기존 사용자별 표시 조건을 함께 적용한다.
현재 확인된 다른 업무 화면의 서비스 진입 링크는 이 사이드바에 모여 있다.
서비스 내부 화면의 탐색 링크 및 직접 URL 접속은 기존 기능을 유지한다.
설정은 세션에 저장하지 않고 현재 요청의 확정된 테넌트·그룹 문맥에서 읽으므로
중앙 변경과 그룹 전환은 다음 페이지 요청에 반영된다.

**이 설정은 이용 차단이나 권한 부여가 아니다.** 재무 조회는 `finance.view`,
변경은 `finance.view + finance.edit`를 계속 요구한다. 계약/프로젝트의 재무
이벤트·첨부·캘린더에도 기존 재무 권한이 유지된다. 메뉴 숨김으로 재무 이벤트를
추가로 숨기거나 권한을 회수하지 않는다. 업무 데이터 삭제, 사용자 역할 변경,
QGIS/QField 서버 접근 제한도 수행하지 않는다.

권한 기준: [Finance 권한 분리](../finance/finance-permission-rollout.md).
실제 서비스 접근 차단은 별도 범위이며 같은 설정을 권한으로 오인하지 않는다.

## 코드와 검증

- `control/views_users_admin.py`, `control/views_groups_admin.py`: 중앙 관리자 화면
- `control/services/central_account_erasure_service.py`: 기존 삭제·익명화
- `control/services/service_menu_visibility.py`: 중앙 설정과 요청별 메뉴 문맥
- `geoflow_ops/templates/geoflow_ops/partials/sidebar.html`: 기존 권한과 표시 설정 결합
- `control/test_admin_visibility.py`: 삭제/비활성 구분, 그룹 격리, 권한 불변성

## 적용·되돌리기 및 현재 상태

구현 준비 상태이며 운영 DB 조사·migration·배포는 이 변경에 포함하지 않는다.
운영 적용 전 중앙 `control.0007_admin_visibility`의 계획과 기존 그룹 삭제 컬럼을
읽기 전용으로 확인하고, 승인된 중앙 migration 후 코드 배포를 수행한다.
테넌트 migration은 없다. 코드만 먼저 배포되면 서비스 메뉴 설정은 비활성화되고
기존 메뉴와 사용자 목록을 유지한다. 사용자 삭제 표시는 migration 이후 완성된다.
이 호환 처리는 모든 운영 중앙 DB에 0007 적용을 확인한 후 제거할 수 있다.

코드 롤백 시 새 테이블·삭제 표시를 보존한다. 0007은 감사 표시를 지우지 않도록
역방향 DDL을 제공하지 않는다. 구버전으로 롤백한 기간의 신규 익명화 기록은
재배포 전에 동일한 보수적 조건으로 추가 이관 여부를 확인해야 한다.
