# 기업 대표페이지

## 목적과 적용 상태

`나의 기업정보 → 기업정보`는 선택한 기업의 현황을 한 페이지에 보여준다.
현재 테넌트의 회사·자회사는 선택 상자로 전환하고 편집은 별도 페이지에서 한다.
AdminKit Pro의 기존 `base_tenant.html`, `control/css/light.css`, `control/js/app.js`
카드·탭·테이블·Chart.js를 재사용한다. 외부 UI 패키지나 별도 인증 흐름을 추가하지 않는다.

이 PR은 구현 및 격리 검증 단계이며 운영 활성화 완료를 뜻하지 않는다.
`GEOFLOW_COMPANY_OVERVIEW_ENABLED=0`(기본값)이면 기존 화면을 유지한다.
운영 DB 변경·서비스 재시작은 AGENTS.md의 별도 운영 승인을 필요로 한다.

## 화면과 업무 규칙

- 진입 시 테넌트별 마지막 선택 기업, 지정 기본 기업, 이름순 첫 기업 순으로 선택한다.
  회사가 하나이면 선택 상자를 숨긴다. 기업이 없으면 기존 생성 안내를 유지한다.
- 회사 정체성은 `ops.my_org_units`를 그대로 사용한다. 기업형태, 기업규모,
  업종·사업내용·설립일·연락처를 보여주며 법인번호·자본금 등은 펼쳐 본다.
  `type`의 자유 텍스트를 법인/지점 관계로 추정하지 않는다.
- 상위 기업과 기업/지점 구분은 명시적으로 입력한다. 자기 참조, 순환 관계,
  지점을 상위 기업으로 지정하는 입력을 거부한다. 지점은 상위 기업이 필요하다.
  선택 기업의 값만 표시하며 자회사·지점 실적을 자동 합산하지 않는다.
- 매출은 연도별 원 단위 수기 입력, 결산일, 출처, 확정/잠정, 증빙을 보존한다.
  대표 카드는 최근 확정 매출, 차트는 잠정 포함 자료를 표시한다.
  없는 값은 공란이며 실제 0과 구분한다. finance 전표/입금 합계로 대체하지 않는다.
- 현재 인원은 `hr.employee_profile`의 선택 회사, 삭제 여부, 입퇴사일,
  HR의 퇴직 상태 설정을 적용해 집계한다. 휴직자는 고용관계가 유지되므로 포함한다.
  입사일이 없고 퇴직으로 표시되지 않은 직원도 포함한다. 직원 개인정보는 반환하지 않는다.
- 과거 인원은 근거가 있는 연말 수치만 별도 입력한다. 현재 HR 소속을 과거로 역산하지
  않는다. 3/5/10년 차트는 직전 완료 연도까지이며 없는 기간은 선으로 연결하지 않는다.
  자동 연말 스냅샷 배치, OCR, 재무/외부평가기관 API는 후속 범위다.
- 등록/신고/인증은 종류·명칭·번호·기관·발생일·상태·선택 만료일·복수 증빙으로 관리한다.
  이름은 자유 입력으로 업종별 고정 목록을 강제하지 않는다. 파일은 선택 사항이며
  없는 경우 증빙 미등록으로 표시한다. 현황 건수는 유효한 최신 이력 수다.
- 갱신·취소는 기존 이력의 `갱신·취소 이력 추가`에서 새 발생일로 등록한다.
  `previous` 연결로 원본을 보존하고 하나의 이력은 한 번만 승계할 수 있다.
  원본 입력 오류는 편집으로 정정한다. 취소 상태 변경은 새 이력을 만들도록 제한한다.
- 신용평가는 기관·평가종류·등급·평가일·만료일·재무 기준일을 이력별로 저장한다.
  대표 등급은 회사별 하나를 사용자가 지정한다. 기관별 등급 서열을 임의 비교하지 않는다.
  대표 등급의 만료 여부와 기관/평가종류를 함께 표시한다.
- 자동 타임라인은 등록/신고/인증과 신용평가의 원본당 하나의 `ProcessEvent`를 사용한다.
  같은 원본의 정정은 동일 이벤트를 갱신하고 파일 업로드만으로 새 이벤트를 만들지 않는다.
  직접 입력 이벤트는 별도로 지원한다. 발생일 내림차순, 동일 발생일은 생성 시각 내림차순으로
  기존 공통 정렬을 사용하며 수정 시각으로 순서를 바꾸지 않는다.

## 데이터 소유와 권한

모든 신설 테이블은 **tenant DB의 ops 스키마**에 속한다. 중앙 DB에 기업 실적을 저장하지 않는다.

| 자료 | 소유 테이블 | 다른 영역과의 관계 |
|---|---|---|
| 기업 식별자·기존 기본정보 | `ops.my_org_units` | 기존 HR·계약·프로젝트 참조 유지 |
| 기업 확장정보·상위 기업 | `ops.company_profile` | 회사당 1개 |
| 업등록·신고·인증 | `ops.company_registration` | 회사, 이전 이력, 자동 이벤트 |
| 연도별 매출 | `ops.company_revenue` | 회사+연도 유일 |
| 과거 연말 인원 | `ops.company_headcount` | 회사+연도 유일; 현재 HR 인원과 구분 |
| 신용평가 | `ops.company_credit` | 회사별 대표 평가 유일 |
| 자료-증빙 연결 | `ops.company_evidence` | 원본 종류/UUID와 기존 Attachment 연결 |
| 자동/직접 이벤트 | 기존 `ops.process_events` | orgunit scope, 원본 payload |
| 파일 | 기존 `ops.attachments` | 기존 S3 업로드·검증·소프트 삭제 재사용 |

조회/편집은 기존 `directory.view`/`directory.edit`를 서버에서 검사한다.
기업 접근 정책은 현재 테넌트의 orgunit 정책을 재사용한다. 사용자별 회사 제한 정책을 새로
만들거나 tenant 경계를 합치지 않는다. 회사 UUID와 첨부 UUID는 모두 tenant 연결에서 확인한다.
매출 조회는 추가로 `finance.view`, 매출/신용평가 편집과 재무 증빙 쓰기는
`finance.view`+`finance.edit`가 필요하다. 대표 신용등급 요약은 기업 조회 권한으로 표시한다.

신규 매출·평가 증빙은 `company_financial` purpose로 저장한다. presign/commit/미리보기/
다운로드/삭제의 공통 경로에서도 directory+finance 권한을 검사한다. 일반 사업·등록 파일과
재무 파일을 잘못 연결하거나 다른 회사 파일을 연결할 수 없다. 파일 연결 해제는 파일 삭제가 아니다.
기존 사업·등록 및 인증·평가 문서는 원래 권한과 내용 그대로 문서함에 남긴다.
기존 공개 범위의 평가서를 신규 재무 증빙으로 조용히 복제/분류하지 않는다. 담당자가 신규
재무 증빙으로 등록하고 기존 파일의 공개 여부를 확인해야 한다. 자동 파일명 추론/백필은 없다.

원본 연결 자동 이벤트는 공유 이벤트 API에서 독립적으로 수정/삭제/첨부할 수 없다.
해당 원본 편집을 통해서만 변경한다. 회사 전체 저장을 잠금으로 직렬화하고 원본+이벤트+
증빙 연결을 한 transaction에서 저장한다. 신규 업로드 자체는 기존 S3 API와 별도 transaction이며
폼 검증 실패 시 업로드된 파일은 기업 문서로 남고 다음 입력에서 다시 연결할 수 있다.

## 코드와 검증

- `company_models.py`, `company_forms.py`: typed facts/입력 검증
- `services/company_overview.py`: HR 집계, 연도별 자료, 원본 이벤트/증빙 규칙
- `views_company.py`: 읽기/편집/회사 선택; 기존 `views_myinfo.py`가 기능 플래그로 연결
- `myinfo/company_overview.html`, `company_edit.html`: 대표/편집 화면
- 기존 `_company_organization.html`: 조직 UI를 조회/편집 호환 경로에서 재사용
- `scripts/ci/test_company_overview.py`: 배포 설정을 읽지 않는 격리 검사
- `company-overview-tests.yml`: disposable PostgreSQL에서 0049 적용/역적용,
  원본 이벤트 멱등성, 권한, HR 필터, 첨부 소유권, 유일성, transaction 회귀 검증

로컬에서는 DB 없는 테스트/템플릿 렌더/JS 문법을 확인한다. PostgreSQL 검증은 CI의 합성
데이터베이스에서 수행한다. 운영 실계정 화면·실제 HR 자료·실제 S3 업로드 확인은 활성화 후 별도다.

## 운영 활성화와 롤백

1. PR 최신 HEAD의 기능/권한 검사와 PostgreSQL 검사를 통과시킨다.
2. 대상 tenant, 배포 SHA, 0049 추가 테이블 적용, 기능 플래그 변경 및 서비스 재시작에 대해
   정확한 운영 승인을 받는다. 기존 migration 적용 상태를 읽기 전용으로 확인한다.
3. 해당 tenant에서 **0049만 새로 적용되는 계획**인지 확인한다. 0048까지 선행 이력이
   불일치하면 중단한다. 이 기능을 위해 미승인 GIS/기타 migration을 함께 실행하지 않는다.
4. 기존 tenant migration context/router를 사용해 해당 tenant에 0049를 적용한다.
   중앙 DB, 전체 tenant 일괄 migrate, provisioning executor를 사용하지 않는다.
5. 검토된 코드를 배포하고 대상 런타임의 `GEOFLOW_COMPANY_OVERVIEW_ENABLED=1`을 설정한다.
   플래그는 런타임 단위이므로 그 런타임이 서비스하는 모든 tenant가 준비되었는지 확인한다.
   미준비 tenant가 있으면 활성화하지 않는다. protected production Environment 승인을 우회하지 않는다.
6. 실계정에서 회사 전환, 편집 저장, HR 인원, 재무 권한 없는 계정, 증빙, 최신순 타임라인을 확인한다.

이 migration은 기존 기업/HR/파일을 백필하거나 삭제하지 않는다. 롤백은 먼저 플래그를 끄고
기존 화면으로 복귀한다. 신규 자료를 보존하기 위해 운영에서 0049 역적용을 기본 롤백으로 쓰지
않는다. DB 역적용은 신규 6개 테이블의 자료를 지우므로 별도 백업·승인 없이는 수행하지 않는다.
