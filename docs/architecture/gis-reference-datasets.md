# 중앙 GIS 공통 참조자료

## 목적과 현재 범위

도엽·법정동·행정동·지적도·기준점처럼 여러 업무에서 함께 사용하는 공식 자료의
출처와 원본 버전을 중앙에서 관리한다. 재질·용도 등의 코드 ID/명 목록은 기존
`gis.definition_code*`가 계속 담당한다. 공간 참조자료를 참조코드 행으로 저장하지 않는다.
GIS 모델 기준은 [GIS 데이터 모델](gis-data-model.md)을 따른다.

현재 구현은 **관리·원본 보관·브이월드 공통 키·공간조회 미리보기와 프로젝트 조회 API**다. 운영 적용·실제 자료 등록·클라이언트 속성 저장 연동 완료는 각각 구분한다.

| 기능 | 구현 상태 |
|---|---|
| 중앙 자료 등록·수정·비활성·검색·종류 필터 | 구현 |
| 공급기관 API/파일/게시판 연결 등록 및 여러 자료에서 재사용 | 구현; 브이월드는 고정 공식 endpoint로 조회, 일반 URL 자동 수집은 미구현 |
| 서버 비밀 참조 연결·유지·해제, API 응답에서 참조 원문 제외 | 구현; 브이월드 키 입력은 전용 Secrets Manager 버전으로 보관 |
| ZIP 등 원본 업로드, 버전 보관, SHA-256, 관리자 다운로드 | 구현; 기존 비공개 버킷 설정 시 기본 활성, 명시적 false로 중단 가능 |
| 등록·변경·원본 저장 성공/실패 이력, 50건 단위 페이지 | 구현 |
| ZIP 경로·중복·심볼릭링크·해제 크기·비율·무결성·SHP 구성 검사 | 구현; 압축을 파일시스템에 해제하지 않음 |
| SHP/GPKG/GeoJSON 레이어·필드 조회 및 정확한 공간중첩, CSV/XLSX 명시적 X/Y 좌표 목록 | 구현; 임시 조회이며 영구 정규화·승인 워크플로는 별도 |
| API 수집, URL 변경 감지·자동 갱신·예약 작업·알림 | 후속 구현 |
| 프로젝트 접근 확인 후 서버 객체 도형으로 조회, 비밀 없는 배경 타일 프록시 | 구현; QGIS 로컬 QC/Structure UI 소비 연결은 후속 |

관리 화면에 실제 파일·API 자료가 있는 것처럼 예시 데이터를 심지 않는다.
미연결 자료는 미연결로, 보관 원본은 개수로 표시한다. API 조회 설정과 원본 조회 상태를 구분한다.
조회는 객체에 지번·PNU·법정동·도엽번호 등을 입력하기 위한 속성 취득 목적이며,
측량자료 사용 적합성을 근거로 일괄 차단하지 않는다. 조회 API는 기존 객체를 자동 수정하지 않는다.

## 원본과 소유 경계

현재는 중앙 공통자료만 관리한다. 회사·프로젝트 전용 비공개 자료는 이 화면에
등록하지 않는다. 제한자료의 소유자·이용허용 범위와 테넌트별 공급 권한은
후속 설계에서 정한 뒤 소비 API를 연다. 관리 API는 중앙 관리자 전용이며 공통자료 소비는 프로젝트 접근을 확인한 별도 조회 API를 사용한다.

- 중앙 `default.gis.reference_source`: 공급 연결, 연결 방식, 공개 기본 주소,
  서버 비밀 참조, 활성 여부, 변경 revision.
- 중앙 `default.gis.reference_dataset`: 불변 자료 코드, 표시명, 종류, 지역,
  제공기관, 설명, 이용조건, 공급 연결, 활성 여부, 변경 revision.
- 중앙 `default.gis.reference_version`: 원본별 불변 UUID·버전명·제공 기준일,
  제공처 CRS 표기, 파일명·크기·해시·비공개 저장 키·저장 상태.
- 중앙 `default.gis.reference_event`: 변경 주체 UUID, 대상, 작업 종류, 처리 시각.
  주체 UUID는 계정 삭제 뒤에도 이력을 보존하기 위해 users FK로 묶지 않는다.
- 원본 파일: 기존 비공개 S3 버킷의
  `central/gis/references/<dataset_uuid>/<version_uuid>/original.<확장자>`.
  사용자 입력 경로, tenant 파일 경로, 공개 MEDIA 경로를 사용하지 않는다.

기존 업무정의·참조코드는 파일의 버전/저장 상태를 표현하지 않으며,
기존 첨부 서비스는 테넌트 업무 레코드에 귀속된다. 그래서 중앙 메타데이터
4개 테이블을 추가하고, 기존 중앙 관리자 검증·S3 클라이언트·암호화·다운로드
서명 기능을 재사용했다. 테넌트 DB, 프로젝트, GIS 시설물 원본은 변경하지 않는다.

## 현재 사용 흐름

1. 중앙 → **GIS 공통 참조자료** → API·파일 연결에서 공급처를 등록한다.
   연결 방식은 수동 업로드/API/파일 주소/자료 게시판이다.
2. 자료 목록에서 자료명, 안정된 코드, 종류, 지역, 제공기관, 출처·이용조건을
   등록하고 공급 연결을 선택한다. 연결은 나중에 지정해도 된다.
3. 운영 저장 준비 후 자료명을 눌러 원본 버전을 추가한다. ZIP을 직접 풀 필요가 없다.
   현재 허용 형식은 ZIP/GPKG/GeoJSON/CSV/XLSX/PDF, 파일당 100MB다.
   다중 SHP는 각각 SHX·DBF·PRJ를 포함해야 한다. 중첩 ZIP·실행파일·암호화 ZIP은 거절한다.
4. 저장 성공 시 `원본 보관됨`이 된다. 자료 상세의 공간조회에서 레이어·필드·좌표계를 확인한다.
   같은 버전명은 중복 등록할 수 없고, 기존 파일 교체·삭제 기능은 제공하지 않는다.
5. 갱신 이력에서 설정 변경과 원본 저장 결과를 확인한다. API 키 원문·비밀 참조·S3 키는
   이력 및 목록 응답에 포함하지 않는다. 원본 다운로드는 관리자 검증 후 60초 서명 URL로 제한한다.

`pending → stored / failed`는 **파일 저장 상태**일 뿐, 도형/내용 검수 상태가 아니다.
저장 실패는 기존 보관 파일을 변경하지 않는다. 저장 요청 전에 pending 행과 키를
커밋하므로 S3 시간초과 또는 최종 DB 기록 실패 시에도 재조사할 키가 남는다.
자동 재시도·고아 파일 삭제는 아직 없다. pending 장기 잔류/failed 원본을 운영자가
DB·스토리지 조회로 조정하기 전 같은 버전명을 다시 사용하지 않는다.

## API 인증정보

주소에는 인증키, 사용자·비밀번호, 쿼리, fragment를 허용하지 않는다. 실제 요청은
아직 실행하지 않는다. 서버 비밀 참조는
`aws-secretsmanager:geoflow/gis/references/<이름>#<json_key>` 형식만 등록한다.
키 원문을 DB·브라우저 저장소·Profile·QGIS에 넣지 않는다. 브이월드 전용 입력은 아래의 공통 키 저장 절차를 따른다.

일반 연결 설정의 서버 참조 입력은 비밀번호 입력으로 표시한다. 기존 참조는 재전송하지 않고
`서버 참조 등록됨 · 접속 미검증`만 표시한다. 비우고 저장하면 기존 연결을 유지하고,
명시적인 연결 해제 또는 API 외 방식으로 변경할 때 해제한다.

브이월드 공통 키 입력·조회는 아래 절차로 구현했다. 일반 API의 사용자별 인증 방식과 자동 수집 adapter는 여전히 별도다. 이번 코드 작업 중 실제 키·비밀을 만들거나 IAM을 넓히지 않는다.

## 상세 화면 구성

기존 중앙 레이아웃과 사이드바를 재사용한다. 상단은 제목·설명·GIS 업무정의 이동,
그 아래는 현재 사용 가능 범위 안내와 3개 작업 탭이다. 기술 설정을 목록에 길게 나열하지 않는다.

| 화면 | 구성과 동작 |
|---|---|
| 자료 목록 | 자료명 검색, 종류 선택, 비활성 포함, 자료 등록 버튼. 행은 자료명/종류/지역·제공기관/자료 연결/보관 원본/사용 상태/설정 |
| 자료 등록·설정 | 모달에 이름·종류·불변 코드·지역·기관·연결·설명·이용조건·활성. 저장 충돌 시 새로고침 안내; 임의 덮어쓰기 금지 |
| 자료 상세 | 자료 설명과 출처·이용조건, 원본 버전 목록, 새 원본 보관. 날짜·좌표계는 버전별 기록 |
| API·파일 연결 | 연결명/방식/제공처 링크/인증 등록 여부/활성/설정. 주소 등록을 접속 성공으로 표시하지 않음 |
| 연결 등록·설정 | 연결명·방식·공개 주소·서버 비밀 참조·명시적 참조 해제·활성. 참조 입력은 원문 재조회 없이 교체만 가능 |
| 갱신 이력 | 한국 시각 처리 일시/자료 또는 연결/작업/버전, 이전·다음. 원본 저장과 실제 공간조회 결과를 구분하는 안내 |

자료 종류의 서버 키와 한국어 표시명을 분리한다. 법정동과 행정동도 별도 종류다.
지역명·기관명·파일명 문자열로 처리 규칙을 결정하지 않는다.

## 장기 갱신·배포 설계 (미구현 부분 포함)

### 공급·갱신

| 공급 방식 | 가져오기 | 자동 갱신 조건 |
|---|---|---|
| 공식 API | 서버 adapter가 페이지/범위별 수집 | 인증·할당량·약관·응답 필드·CRS를 검증한 연결에 한해 주기 활성화 |
| 고정 파일 URL | 서버 다운로드 후 해시/ETag/수정일 비교 | 공개 다운로드와 안정된 응답이 확인된 경우 |
| 게시판·자료 안내 링크 | 공급기관 전용 adapter 또는 수동 업로드 | 링크만 등록한다고 자동화되지 않음 |
| 승인·로그인 후 발급 자료 | 승인받은 담당자 수동 업로드 우선 | 이용권한과 허용된 공식 연동 경로가 있을 때 별도 설계 |

API URL 문자열만으로 임의 인터넷 요청을 실행하지 않는다. adapter별 허용 도메인,
DNS/리다이렉트의 사설망 차단, 시간·응답 크기·페이지 제한, 요청 로그 키 마스킹을
구현한 뒤 수집 실행 버튼을 추가한다. 자료별 주기와 중복 실행 방지를 서버에서 관리한다.

새 원본 → 격리 검사 → 레이어 인식 → 좌표계·필드 연결 → 공간검증 → 검토 → 사용 승인
순서다. 여러 레이어는 테이블로 선택하고, 모르는 좌표계는 추측하지 않는다.
원본 CRS/정규화 CRS/변환 정보를 구분한다. 지적도 API는 객체에 필요한 지번·PNU 속성을 취득하는 용도로 연결한다. PDF 좌표를 검증 없이 공간 원본으로 승격하지 않는다.

상세 화면에 이후 `레이어·필드`, `검수 결과`, `사용 버전` 영역을 추가한다.
수집 상태와 사용 버전을 분리하여 실패·검토 대기 중에도 이전 승인 버전을 유지한다.
대규모 삭제·범위/좌표 변화는 관리자 검토 후 전환하며 실행 중인 작업 버전은 바꾸지 않는다.

### QGIS·웹 소비

중앙 공통 레퍼런스를 프로젝트에 복제 저장하지 않는다. 서버는 프로젝트·자료 권한과
사용 승인 버전을 확인하여 작업 영역에 필요한 부분만 반환한다. QGIS는 메모리 또는
임시 GPKG를 같은 작업의 Preview/실행에서 재사용하고 종료·취소 시 정리한다.
비정상 종료 잔여물은 다음 시작 시 정리한다. 웹은 같은 서버 공간조회·계산 서비스를 사용한다.

결과에는 자료 UUID·사용 버전 UUID·규칙·실행 시각·필요한 출처를 남겨 재현한다.
출력 결과의 참조 이력은 원본 파일 복사와 다르다. 공유 캐시를 만들더라도 권한이 다른
자료를 함께 제공하지 않는다. 프로젝트의 객체 도형을 사용하는 조회 API는 구현되었다. 클라이언트 임시 캐시와 구조화 저장 소비는 후속이다.

## 적용·검증·되돌림

- 코드: `control/services/gis_references.py`, `gis_reference_files.py`,
  `control/views_gis_references.py`, `control/templates/control/gis/references.html`.
- 중앙 migration: `control.0011_gis_reference_datasets`. 기존 자료·코드 이관은 없고 빈 저장소로 시작한다.
  운영 배포 승인을 받으면 기존 production Environment 보호 배포에서
  `deploy_gis_reference_datasets --check → --apply → --verify`를 사용한다.
  중앙 `0009` 기반 위에서 `0010 → 0011`의 정확한 적용 상태를 확인한다.
  `0010` 미적용 시 기존 migration의 SQL로 중앙 직원 등록 **빈 이력 테이블**을 먼저 추가한 뒤
  참조자료 `0011`을 적용한다. 계정·그룹·역할 행 및 테넌트 데이터는 변경하지 않는다.
  두 단계의 DDL과 적용 기록은 하나의 트랜잭션이며 다른 migration을 따라 적용하지 않는다.
  선행 테이블만 존재하고 기록이 없는 경우에도 가짜 적용 처리 없이 중지한다.
  최초 운영 배포는 `0010`이 이미 적용되었다고 가정하여 사전 점검에서 중단되었다.
  로그상 참조자료 DDL 전 중단·이전 코드 복구·서비스 기동을 확인했고,
  미적용 `0010`을 포함한 격리 DB 회귀 검증과 위 순차 적용으로 배포 절차를 보완했다.
  부분 생성·적용 기록과 테이블 불일치는 자동 복구하지 않고 중지한다.
  재실행은 기존 등록 자료를 보존하며, 검증은 실제 관리자 GET 화면/API 200과 익명 403을 확인한다.
  `migrate_all_tenants`를 실행하지 않는다.
- 원본 저장은 `AWS_S3_BUCKET`이 설정된 기존 비공개 버킷에서 기본 활성화한다.
  `GEOFLOW_CENTRAL_REFERENCE_UPLOAD_ENABLED=false`로 명시적으로 중단할 수 있다.
  기존 `AWS_S3_BUCKET`, SSE/KMS 설정과 새 중앙 prefix의 정확한 IAM 권한을 사전 확인한다.
  코드 작성은 live S3 PUT/IAM 수정/비밀 생성 승인과 다르며 이번 작업에서는 실행하지 않는다.
- 웹 서버 요청 한도는 multipart 여유를 포함하여 설정한다. 동시 업로드·임시 디스크 용량도 운영 전 확인한다.
- URL 공급은 아직 외부 네트워크 요청을 하지 않고, 파일 검사는 공간 적합성이나 악성코드 종합검사를 대신하지 않는다.
- 권한/CSRF/비밀 미노출/ZIP/저장 실패 관련 단위 테스트와, 격리 PostgreSQL의 migration·FK·유일성·버전 상태 테스트를 둔다.
  이 변경은 공간 테이블을 생성·변경하지 않아 해당 migration 리허설에는 PostGIS가 필요하지 않다.
- 코드 롤백 시 신규 테이블·파일을 보존한다. migration reverse는 비파괴 noop이다.
  migration을 되돌려서 재적용하지 말고 적용 기록을 유지한다. 테이블/원본 삭제는 별도 승인 절차다.
- 운영 배포·migration·버킷 업로드·자료 사용 승인은 별도 단계이며 이 문서의 구현 상태와 구분한다.

## 브이월드 공통 키와 현재 공간조회

### 키 등록·공유

`API·파일 연결` 상단에서 새 키와 발급 시 등록한 서비스 도메인을 입력한다.
입력은 password 폼으로 전송하고 성공·실패 후 브라우저 입력칸을 비운다.
저장된 키 원문을 GET 응답·브라우저 저장소·Profile·QGIS·감사 이력으로 반환하지 않는다.
키를 아직 등록하지 않았다면 기존 서버 `VWORLD_API_KEY`를 재사용한다.

키 원문은 서버가 고정된 Secrets Manager 이름 `geoflow/gis/references/vworld`에 보관한다.
중앙 `gis.reference_provider_credential`은 provider·AWS 비밀 버전 ID·도메인·revision·관리자·시각만
보관한다. 하나의 공급기관 키는 여러 연결과 배경지도에서 공유하므로, 자료 연결별 `secret_ref`에
원문이나 서로 다른 최신 버전을 반복 저장하지 않고 작은 공통 자격증명 테이블을 추가했다.
AWS 버전을 DB에 명시적으로 고정하여, 외부 저장 성공 뒤 DB 트랜잭션이 실패해도 이전 키를 유지한다.
공통 키 교체는 기존 환경변수나 GitHub Secret을 덮어쓰지 않는다.
같은 AWS 버전은 서버 프로세스 메모리에서 최대 4개 버전만 재사용한다.
공유/영구 캐시에는 키를 쓰지 않고, DB 버전이 바뀌면 새 키를 읽는다.

서버 역할에는 이 **정확한 이름의 비밀**에 대한 CreateSecret·PutSecretValue·GetSecretValue 권한이
필요하다. AWS의 비밀 ARN 접미사를 포함한 단일 이름 범위로 제한하며 다른 테넌트 비밀이나
전체 비밀에 권한을 넓히지 않는다. 이 코드 변경에서 IAM·실제 비밀·키는 생성/수정하지 않았다.
실제 키 등록과 조회는 운영의 정확한 IAM 설정 및 발급 키를 사용하는 별도 검증 대상이다.
등록 성공은 안전한 저장 확인이며, 서비스별 접속 성공은 공간조회에서 확인한다.

`지번·법정동 자료 연결`은 공식 데이터 endpoint 하나를 재사용해 두 자료 정의를 등록한다.
이미 존재하는 자료를 초기화하지 않으며, 같은 코드가 다른 연결을 가리키면 자동 덮어쓰기 없이 중지한다.
표시명을 변경해도 endpoint·자료 종류·서비스 ID로 동작한다.

| 서비스 | 공식 데이터 ID | 목적 |
|---|---|---|
| 지번·PNU | LP_PA_CBND_BUBUN | 중첩 필지의 실제 속성 조회 |
| 법정동 | LT_C_ADEMD_INFO | 읍면동 경계의 실제 이름·코드 조회 |
| 법정리 | LT_C_ADRI_INFO | 리 경계의 실제 이름·코드 조회 |

속성명은 응답에서 읽어 사용자가 선택한다. 필드명이 없으면 값을 만들어 넣지 않는다.
법정동과 행정동을 혼용하지 않으며 이번 API preset은 법정동·법정리다.
근거: [브이월드 공식 행정구역 예제](https://github.com/V-world/V-world_API_sample),
[브이월드 공식 QGIS 레이어 정의](https://github.com/V-world/V-QGIS/blob/main/constants.py).

외부 호출은 고정된 `api.vworld.kr` HTTPS endpoint만 사용한다. 사용자 URL을 호출하거나
다른 호스트로 리다이렉트를 따라가지 않는다. 인증키가 포함된 URL·원문 예외·오류 응답을
로그나 사용자에게 반환하지 않는다. 도메인과 Referer를 함께 사용한다.
한 요청의 시간·응답 크기·후보 수를 제한하고 100개 초과/누락된 API 결과는 부분 성공으로 처리하지 않는다.
배경지도는 같은 키를 서버 프록시에서 사용하며 브라우저 지도 설정에는 GeoFlow 타일 URL만 넣는다.

### 원본 파일·레이어·좌표 목록

자료 상세에서 원본 버전을 고른 뒤 `파일 레이어 읽기`를 누른다. SHP/GPKG/GeoJSON은
실제 레이어·필드·좌표계를 읽고, 여러 레이어가 있으면 직접 선택한다.
도곽은 면 레이어의 도엽번호 필드를 선택한다. XLSX 또는 UTF-8 CSV 기준점 목록은
첫 행의 필드명을 읽고 X·Y 필드와 기준점 좌표계를 명시한다. X/Y를 이름으로 추측하거나 뒤집지 않는다.
Excel은 활성 시트, 첫 행 필드명, 최대 200열·50,000개 데이터 행을 지원한다.
PDF는 성과 원본 열람·보관 대상으로 유지하며 좌표를 임의 추출해 점으로 만들지 않는다.

서버는 등록 버전의 크기·SHA-256을 확인하고 임시 디렉터리에서만 읽는다.
ZIP은 경로·중복·심볼릭링크·크기·SHP 구성 검사를 다시 거친 뒤 임시 해제한다.
도형 해석은 로컬 SHP/GPKG/GeoJSON 드라이버만 허용하고 VRT/외부 원격 소스를 열지 않는다.
성공·오류 모두 임시 파일을 제거하며, 테넌트/프로젝트의 첨부나 영구 레이어로 복사하지 않는다.

### 중첩·선택 규칙

입력 좌표계로 도형을 해석한 뒤 EPSG:4326으로 변환한다. API는 범위 조회 후 GEOS의 실제
intersects로 다시 검사한다. 경계에 걸친 객체도 후보에 포함한다.
파일은 해당 레이어 CRS에서 공간 필터를 걸고 동일한 정확한 중첩 검사를 적용한다.
범위 밖 후보, 불완전한 결과, 좌표계 불명, 잘못된 도형을 정상값으로 처리하지 않는다.
기본 조회 범위는 경위도 폭·높이 각각 0.02도 이하, 입력 도형 5,000좌표 이하로 제한한다.

- `unique`: 한 후보일 때만 값 사용. 여러 후보는 `AMBIGUOUS`, 결과값은 비움.
- `all`: 중첩 후보 모두에서 필드별 중복 없는 값 목록 반환. 임의 문자열 결합 없음.
- `selected`: 현재 중첩 후보의 ID를 사용자가 지정. 후보 밖 ID는 거절.

필지·도곽·법정동이 여러 개면 첫 번째 것을 임의 선택하지 않는다. 반환값에는 자료 UUID,
파일 버전 UUID/해시 또는 API 공급 서비스, 선택 규칙과 후보를 남긴다.
이 미리보기는 `written=false`이며 원본 도형/속성을 수정하지 않는다.
실제 속성 저장은 기존 편집/구조화 승인·검증·저장 경로가 반환값을 소비해야 한다.
QGIS 로컬 QC/Structure의 실제 버튼·Profile 소비 연결은 이 PR에서 수정하지 않는다.

### 서버 API 경계

- 중앙 관리자 POST `/control/central/gis/references/vworld-key/`: 폼의 api_key/domain/revision.
- 중앙 관리자 POST `/control/central/gis/references/lookup/`: 지정 좌표의 원본 inspect/조회.
- 프로젝트 GET `/gis/projects/<project_id>/api/spatial-references/`: 이용 가능한 공통 자료·원본 버전 목록.
- 프로젝트 POST `/gis/projects/<project_id>/api/reference-lookup/`: feature_layer/feature_id,
  dataset_id, 선택한 version_id 또는 service, layer/fields/selection/chosen_id 등 조회 설정.
- 프로젝트 GET `/gis/projects/<project_id>/api/reference-tiles/<style>/<z>/<y>/<x>/`: 비밀 없는 타일 프록시.

프로젝트 API는 기존 maps.view·테넌트·프로젝트 접근·Final Layer Plan을 먼저 확인한다.
객체 도형은 해당 테넌트의 정확한 project_id와 feature ID로 다시 읽는다.
클라이언트가 넘긴 다른 geometry는 사용하지 않는다. 중앙 자료 목록에는 키·외부 비밀 참조·S3 경로를 넣지 않는다.
모든 변경/조회 POST는 CSRF를 유지한다. 임의 URL 다운로드, ID/PW 자동 로그인,
예약 갱신 및 모든 자료의 영구 PostGIS 적재는 이번 범위가 아니다.

### 이번 확장 적용

`control.0012_gis_reference_provider_credential`을 같은 보호 배포의 중앙 전용 apply에 추가한다.
이미 적용된 0010/0011은 건너뛰고 기존 자료·키 등록 이력을 보존한다.
0012는 공통 키 메타데이터 테이블과 이력의 credential_updated 작업 종류만 추가한다.
사전 점검에서 GEOS/GDAL/PROJ를 읽고, 운영 smoke는 관리자 페이지/API·익명 차단·기존 GIS 보존을 확인한다.
실제 발급 키와 사용자가 내려받은 원본을 제공받지 않은 단계에서는 실제 공급자료 조회 완료로 보고하지 않는다.
