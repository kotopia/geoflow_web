# GeoFlow Phase 4 기능·아키텍처 설계 초안 v0.1

- 작성 기준: 2026-08-15 논의
- 상태: 설계 초안 / 구현 전
- 범위: 계약, 프로젝트, 이벤트, 직원, 외부연동, WebGIS, QGIS, 구조화 편집, 과금

## 1. 핵심 결정

- `contract_id`를 업무 계보의 중심키로 사용한다.
- 중앙 카탈로그(Level 1~4)는 업무 정의만 담당한다.
- tenant 프로젝트에는 계약수량, 실제수량, 상태, 완료일, 차이사유, 메모를 저장한다.
- 계약변경·공사중지·재개·기간연장 등은 카탈로그가 아니라 별도 이벤트/히스토리로 관리한다.
- 초기에는 관리부가 계약/이벤트를 입력하고 사업부는 조회한다. 요청·승인·내부결재는 후속 고도화다.
- 작업은 일렬 강제단계보다 병렬 작업 항목 중심으로 관리한다.
- 계약물량과 실제물량이 달라도 완료 가능하며, 차이 사유를 같은 실행 레코드에 남긴다.
- 직원 관리는 자격증·기술등급·경력·프로젝트 투입이력까지를 초기 범위로 한다.
- GeoFlow를 Source of Truth로 두고 Google Sheets 등은 tenant별 API/내보내기로 조회한다.
- QGIS Plugin은 로그인·프로젝트 선택·UI 중심의 thin client로 설계한다.
- WebGIS는 일반 편집/정위치 편집/구조화 편집을 분리한다.
- 구조화 편집은 PostGIS 서버 연산으로 실행하고 프로젝트 단위 과금을 우선 검토한다.

## 2. 현재 코드 출발점

기존 WebGIS 코드에는 권한별 메뉴, 프로젝트 상태필터, Leaflet 기반 지도, GeoDjango Geometry CRUD, 프로젝트 상세수정 등의 구현이 존재한다. Phase 4에서는 이를 폐기하기보다 프로젝트 스코프, 권한, 감사로그, 서버 연산 경계를 강화하는 방향으로 확장한다.

## 3. 공통 아키텍처

- PostgreSQL/PostGIS: 공간 연산, 집계, 길이/면적 계산, 구조화 연산, 정합성 제약
- Django/GeoFlow Server: tenant/project 권한, 업무 규칙, 이벤트, API, 감사로그, QGIS 세션
- Web Frontend: UI/필터/편집도구
- QGIS Plugin: 로그인, 프로젝트 선택, 전문 편집 연결
- 외부 도구: API를 통한 read 중심 소비

## 4. 계약 관리

- 계약 준비 → 계약 완료가 기본 흐름이나, 긴급/선착수를 허용한다.
- 착수계 제출 여부는 별도 속성으로 두어 관공서/민간 프로젝트를 모두 처리한다.
- 관리부가 계약변경, 중지, 재개, 기간연장 이벤트를 입력한다.
- 계약 대시보드는 진행/중지/변경/종료예정/미청구 등 관리부 중심 지표로 구성한다.

## 5. 프로젝트 관리

- 중앙 카탈로그는 “무슨 일을 하는가”를 정의한다.
- tenant의 project catalog 실행 레코드는 계약수량·실제수량·상태·완료·메모를 관리한다.
- 상태 예시: 대기/진행중/완료/보류/취소.
- 기준점측량, 조사측량, 노출관로측량 등은 병렬 처리 가능.
- 선행조건이 필요한 정위치/구조화/성과심사는 필수 작업 완료 후 활성화할 수 있다.
- 계약물량과 실제물량은 독립적으로 관리하며 불일치해도 완료 가능하다.
- 목록 기본값은 현재 관리 대상만 표시하고, 기간/연도/담당자/완료포함 필터를 조합한다.

## 6. 이벤트/히스토리

이벤트 카탈로그 예시: 계약변경, 공사중지, 공사재개, 기간연장, 착수, 납품, 성과심사. 날짜가 있는 이벤트는 캘린더/알림과 연결할 수 있게 한다.

## 7. 직원

초기 포함: 입퇴사/재직, 기본 프로필, 자격증, 건설기술인 등급, 과거 경력, GeoFlow 프로젝트 참여이력. 급여/근태/평가 등 HR 전체는 초기 제외.

## 8. 외부연동

GeoFlow를 데이터 원본으로 두고 tenant별 API로 계약/프로젝트/직원 데이터를 Google Sheets 등에서 조회한다. 외부 시스템의 tenant DB 직접 수정은 지양한다.

## 9. QGIS

1. QGIS Plugin에서 GeoFlow 로그인
2. 서버가 접근 가능한 프로젝트만 반환
3. 기본은 프로젝트 1개를 활성화
4. 대용량 공간데이터는 project-scoped PostGIS 접근을 사용
5. 권한/업무규칙/비밀키는 서버에 둠
6. 수정 이력은 감사로그로 남김

QGIS Plugin에는 tenant 전체 DB의 장기 계정/비밀번호를 저장하지 않는다.

## 10. WebGIS

- 일반 편집: 생성/이동/삭제/vertex/snapping/split/merge
- 정위치 편집: 반복 기하 보정
- 구조화 편집: 위상관계, 중첩, 면→선, 선→점 등 PostGIS 기반 서버 연산

브라우저는 편집 UX를 담당하고 최종 geometry validity, 권한, project scope는 서버/PostGIS가 검증한다.

## 11. 실적 물량

GIS layer와 project catalog item을 매핑하고, line length/area/count를 PostGIS에서 authoritative하게 계산한다. 계약물량 대비 실제물량 차이는 대시보드/준공/정산에 재사용한다.

## 12. 과금 초안

- 기본 GeoFlow: tenant 월 구독 + 사용자 seat 검토
- 일반 WebGIS 편집: 구독 포함
- QGIS Plugin: 구독 또는 전문 seat 옵션
- 구조화 편집: 프로젝트 단위 이용권 우선 검토
- 클릭당 실행 과금은 초기 권장안에서 제외

## 13. 구현 우선순위

- 4A 업무 뼈대: 계약/프로젝트 식별자, 이벤트, project catalog 실행 레코드
- 4B 목록/대시보드: 상태 중심 목록 + 기간/연도/담당자 필터
- 4C 직원/외부연동: 자격·등급·경력 + tenant API
- 4D WebGIS 편집: 일반/정위치 + 실제물량
- 4E QGIS: 로그인/프로젝트 스코프/감사로그
- 4F 구조화 편집: PostGIS job 서비스화 + 과금 정책

## 14. 후속 고도화

- 부서간 요청→승인→내부결재 workflow
- 급여/근태/평가 등 HR 전체
- 회계 ERP 전체
- QGIS 전문 기능의 WebGIS 복제

## 15. 구현 전 확정 항목

- 계약↔프로젝트 1:1 vs 1:N
- 작업 상태 최종 명칭
- 이벤트 유형별 필수필드
- 카탈로그-GIS actual_qty 매핑 규칙
- QGIS project-scoped PostGIS 방식(RLS/view/단기 role/프록시)
- 직원 자격/기술등급 상세 데이터 모델
- 구조화 편집 이용권/재실행 범위

## 최종 설계 문장

GeoFlow는 계약을 시작점으로 프로젝트, 카탈로그 업무, 이벤트, 직원 투입, 공간데이터 실적을 하나의 계보로 연결한다. WebGIS와 QGIS는 역할이 다른 클라이언트이며, 핵심 권한·업무규칙·공간 연산은 GeoFlow Server/PostGIS에 집중한다. 외부 시스템은 API로 연동해 단계적으로 GeoFlow 중심 구조로 전환한다.
